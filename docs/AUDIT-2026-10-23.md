# FLIP debug and publication audit

Superseded input/install choices: the current beta.3 uses configurable keys, Down Arrow as the new-profile default, both held-key/drag orders and default installer integrations. See [the current report](CUSTOM-SHORTCUTS.md). The sections below retain the earlier beta.2 evidence.

Candidate: 0.4.0-beta.2, local changes based on the existing beta.1 source. No GitHub push, visibility change, release or social publication was performed.

## Corrected

**Explorer copies during Ctrl-drag.** Raw Input only observes Ctrl; it does not suppress Explorer's copy modifier. The user selected the physical `<>` key beside left Shift on Italian ISO keyboards. It is now the default (scan code 0x56, with VK_OEM_102 fallback when no scan code is available); no Ctrl, Alt or Shift is needed. Saved Ctrl/F8/F9 choices migrate to this key. The briefly proposed F8/F9 choice was withdrawn because it did not meet the requested keyboard position. Native drag/drop outside the wheel still belongs to Windows; Escape cancels before mouse release. Physical interaction acceptance is still required. Key identity: [Microsoft virtual-key definitions](https://learn.microsoft.com/en-us/windows/win32/inputdev/virtual-key-codes).

**Inconsistent tick requests.** Replaced SoundPlayer with WinMM asynchronous playback of the original WAV from pinned memory. Removed the 55 ms event suppression and per-hover disk logging. Rapid sector changes restart the tick instead of scheduling stale hover feedback. This is a code-level correction, not an acoustic latency measurement or headphone acceptance. See [Microsoft's PlaySound contract](https://learn.microsoft.com/en-us/previous-versions/dd743680(v=vs.85)).

**False document failures and leftover temporary folders.** The first full run found read-only hidden LibreOffice lock files. Recursive directory deletion threw after conversion, causing failure reports and residual job directories. Cleanup now validates the exact parent and generated GUID name, refuses reparse points, and clears read-only attributes only within the owned job tree. A synthetic regression test covers the lock-file case and refusal to clean an unowned directory.

**CLI parsing.** Missing values for evidence/trigger/report produce explicit argument errors. File arguments stop at subsequent options, so `--evidence`/`--report` are not treated as filenames. Null/corrupt trigger preferences fall back through the migration path.

**Build and installation.** The build can target a separate directory and checks whether existing output is locked before writing. Optional Pandoc copying requires the document-engine switch. Added an installer that copies per user, backs up an existing installation and hashes every copied file. It creates shortcuts/startup only on request. Added a recorder that requires an explicit capture rectangle and keeps raw output ignored.

## Security and privacy review

The reviewed Git base has 46 tracked files and six reachable revisions. The audit script checks current tracked text, new unignored source, historical filenames, historical text and commit metadata. No configured secret/private-path pattern matched in the reviewed scans. Patterns include GitHub/OpenAI/AWS/Slack credential forms and private-key headers. This is a bounded pattern scan, not a comprehensive credential or personal-data detector.

Author and committer identities use the existing GitHub noreply address. This still exposes the GitHub identity intentionally. The public wheel PNG was visually inspected: synthetic filename, no personal path visible. The WAV is generated by the procedural source. Other opaque assets, including the icon, are not comprehensively covered by text scanning or metadata inspection; review them before public release.

Ignored workspace contents include builds, downloaded tools, local tests, backups and unrelated tool folders. Do not upload the workspace as a ZIP. `Export-Source.ps1` uses committed source and refuses dirty exports. Runtime logs can contain source/output paths; keep them private or redact them.

The source has no API backend/account requirement in the reviewed conversion path. Process arguments use `ArgumentList`; originals are copied into private conversion jobs; collision-safe output creation and existing file/input/container limits remain in place. This review is not a hostile-document sandbox assessment. Third-party parsers and document engines require continued maintenance.

Online `dotnet list package --vulnerable --include-transitive --no-restore` completed successfully and reported no vulnerable packages for the current sources on 23 October 2026. Initial sandboxed network attempts failed; those errors were not treated as clean results. Native/Pandoc/LibreOffice advisory and binary redistribution review remains distinct from NuGet audit.

## Validation and release limits

- Full conversion suite after the lock-file fix: **99 passed, 0 failed**. The initial failing run is retained locally; final synthetic fixtures verify original preservation, collisions and temporary cleanup.
- Final input/policy/geometry/PCM/CLI/cleanup suite after the ISO key update: **67 passed, 0 failed**. Includes scan-code matching, key up/down, layout-independent identity, rejection of extended codes, aliases and retirement of F8/F9.
- Per-user installer tested with an isolated local destination, including per-file checksums. No Desktop shortcuts, startup settings or context-menu entries were created by that test. This is not a clean-Windows test.
- Upgrade of that isolated destination also passed with a retained backup. The build refuses a locked output directory before restore/publish; this was checked against the running local application.
- The earlier local `app` restart confirmed F8 registration, Pandoc/LibreOffice discovery and one accepted `winmm-memory` audio request. That F8 build was superseded by the user-selected ISO `<>` key. These events do not establish what was heard or physical gesture behavior.
- After the ISO key change, the Italian Windows layout (0x0410) mapped scan code 0x56 to VK_OEM_102 (0xE2). The tested candidate was copied into `app`, its DLL checksum matched, and runtime startup confirmed registration of `<>`. A backup of the previous local application was retained. This verifies configuration and deployment, not a physical Explorer drag.
- Native UI control was attempted with the Windows Computer Use skill, but app approval timed out. No new physical drag/drop, mixed-DPI, subjective audio or recorded-demo evidence is claimed.
- The binary requires final Explorer/Desktop acceptance, startup/reboot acceptance, clean-Windows installation, distribution notices and an explicit signing/trust decision before public release.

Windows CI now checks complete reachable history with checkout credentials disabled. The modified workflow has not run on GitHub. A build emitted NU1900 when cached NuGet vulnerability retrieval failed, even though the separate explicit online vulnerability query succeeded; compiler/publish success is separate from that network warning.
